# HushRaster R1 — Resilient Compact

**Standard status:** implemented in HushRaster 1.0.1.
**Code license:** GPL-3.0-only for this Python implementation.
**Format specification license:** CC0 1.0 Universal.

R1 is the compact, high-correction candidate in the Resilient tree. It aims to retain exact bytes when a modest, localized region of modules is obscured, including by a centered logo. It is custom HushRaster—not QR Code or Data Matrix.

## Raster layout

- Black-and-white PNG; one quiet module around the grid.
- One asymmetric 5×5 finder at the upper-left. The finder template is the R1 format identifier, so R1 avoids the two additional finder blocks that QR-style layouts use.
- Data modules follow in row-major order everywhere outside that one finder. The decoder samples module centers at the selected `--ppm` density and verifies the R1 finder before decoding.
- Use `--ppm 1` for the smallest image; higher PPM is a display/print scaling factor, not additional error correction.

## Frame and integrity

- Payload length 0–254: a single unsigned byte holding the payload length.
- Payload length 255 and above: `0xFF` followed by a four-byte unsigned big-endian length.
- The remaining frame is the exact payload bytes followed by CRC32/ISO-HDLC in four-byte big-endian order. The length prefix is outside the Reed–Solomon code, while payload and CRC are inside it.
- The CRC detects accidental corruption that remains after correction; it is not cryptographic authentication.

## Error correction

R1 uses shortened systematic Reed–Solomon codewords over GF(256), with primitive polynomial `0x11D` and 32 parity symbols per codeword. A codeword has at most 255 symbols, therefore up to 223 data symbols. The last block may be shortened. Interleaving lays out byte symbols from different codewords round-robin, spreading a local run of damaged modules across blocks for larger payloads.

The theoretical symbol-error capability is **up to 16 unknown byte-symbol errors per codeword** (`32 / 2`). This is not equivalent to 16 damaged modules: a byte symbol contains eight module bits, and the number of affected byte symbols depends on the spatial shape and alignment of the damage. A centered opaque 7×7-module logo is covered by an automated test that confirms byte-exact recovery for the recorded sample payload at PPM 1 and 4. The measured side-by-side image is in [`evidence/R1-Compactness-and-ECC-Evidence.png`](evidence/R1-Compactness-and-ECC-Evidence.png), and [`evidence/R1-Evidence.json`](evidence/R1-Evidence.json) stores its machine-readable numbers. It is a tested case, not a universal maximum-logo guarantee.

For very small payloads, the fixed 32-symbol parity cost can make R1 larger than P2. Choose R1 when its additional robustness and logo tolerance matter more than minimum area; choose P2 for a smaller default symbol with adaptive ECC.
